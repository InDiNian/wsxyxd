# 卫戍协议小队规划器

本地运行、面向手机的小队编辑器。选择干员，配置装备和精锐状态，查看核心 / 附加盟约人数与激活条件。无需安装前端依赖。

## 启动

```sh
npm run dev
```

打开 [本地网页](http://localhost:5173/)。开发服务监听所有本机网卡，终端会打印可供同一网络手机访问的地址。

```sh
npm test
npm run build
npm run preview
```

构建产物为 `dist/`，也可直接作为静态网页使用。当前小队的编辑状态保存在浏览器 localStorage 中。命名保存与「我的阵容」功能已移除。

## 数据来源

模式归属、普通 / 精锐特质、盟约人数和效果、装备信息统一来自 [PRTS：卫戍协议·规程 / PRTS盟约记录](https://prts.wiki/w/卫戍协议·规程/PRTS盟约记录)。同构装备对应关系另参考 [变形同构体](https://prts.wiki/w/变形同构体) 天赋表。

- 141 位默认参战干员，一至六阶分别为 19、24、26、27、25、20 位。
- 10 个核心盟约、16 个附加盟约及其真实激活人数、人数条件、层数条件。
- 每位干员的普通 / 精锐特质和特质分类；详情提供职业特性和常规技能等级 4 / 7 作为独立参考。
- 70 件装备，包括基础 / 进阶效果、价格、等阶及本地图标。
- 141 位精二头像与默认完整立绘均为本地 WebP。干员美术资源 © 鹰角网络，来源为 PRTS 对应页面。

默认名单沿用主页面文字速查；原型替代干员不重复列入。记录页另有两个策略专属 / 特殊单位（盟约·辅助干员、“暴躁铁皮”），不作为默认可招募干员，其名称记录于导入报告。

手动资料填写入口、草稿 API 与手动覆盖规则已移除，模式数据不再读取用户填写内容。切换前的原始数据、代码和草稿保留在忽略的 `.local/backups/before-prts-switch-*` 中，不由网页服务公开。

## 小队编辑

- 默认上限 8 人，勾选「已使用人事部文档」后上限设为 9 人，不可累计到 10 人。
- 满员时阻止继续添加；9 人阵容不能直接关闭扩容，需先移除至 8 人。旧版本超过人数上限的小队会保留所有成员，并提示调整，避免静默丢失。
- 每位干员可配置两个装备位。快速选择同构组合会同时配上「变形同构体」和对应装备。
- 仅当同一干员同时携带同构体与已明确对应盟约的装备时，才增加盟约归属。单独装备不增加；原生与装备重复的盟约仍只计 1 人，卸下后立即撤销。
- 转化采用 PRTS 天赋表当前明确列出的对应关系，共 19 件可搭配装备、13 种盟约；维式重锤系列按该表的系列规则处理。未列明的关系不根据装备名称推断。
- 「人事部文档」为消耗型装备，扩容作为小队状态记录，不占干员装备位。其他消耗型装备可查阅效果，不作为持续携带的装备列入装备位。
- 精锐开关影响当前特质展示，并使所有精锐干员参与「绝技」计数。
- 核心盟约通常 3 人激活，6 名不同干员有额外效果。「调和」增加 1 个核心激活人数，单独显示奖励；6 名不同干员条件仍按实体成员判断。「独行」有多名成员时失效。「绝技」按 2 / 5 名精锐判断。
- 层数条件直接展示来源公式，不将 40 层、100 层等误当作人数。当前计算的是小队在场成员；整备区生效的能力保留在盟约说明中。
- 当前小队的编辑状态会保留，命名保存和阵容收藏页已移除。旧版浏览器数据另存为 `lineup-lab:v1:before-pact-overview`，不再展示收藏入口。

## 查阅与筛选

卡牌库支持干员、盟约、特质正文、普通 / 精锐效果和技能名搜索；可结合职业、盟约、一至六阶筛选。

特质标签有「全部」和每种标签的人数。人数依据当前盟约、职业、等阶、搜索条件计算，忽略当前特质标签自身，避免切换标签时错误归零。同一干员重复出现相同标签只计一次。

「盟约与装备」页面提供只读的全部盟约规则与 70 件装备；可搜索装备名、效果和同构转化盟约。

## 更新来源数据

参考数据导入脚本需 Python 的 `requests`、`beautifulsoup4`、`lxml`、`Pillow`。响应缓存在 `.cache/prts/` 中；需要更新来源时删除对应缓存文件再导入。

```sh
python3 scripts/import-prts.py
python3 scripts/import-elite2-avatars.py
python3 scripts/import-pact-records.py
```

第一步更新名单与常规干员资料；第二步更新精二头像；第三步重新接入模式归属、普通 / 精锐特质、人数规则与装备。既有模式资料和精二头像在第一步会保留。

`data/mode-import.json` 记录导入数量、特殊单位排除项和图标下载异常。完整核心盟约成员记录见 `data/core-pacts.json` 与 `docs/core-pacts.md`。

## 文件结构

```text

```


## 盟约进度展示

小队列表上方提供图标速览，显示当前小队涉及的盟约：未激活时较淡，达到第一档后在图标上加一条横杠，第二档加两条。点击图标查看完整说明。

速览的进度与分段条由 `pactProgress()` 统一计算：例如三 / 六人档显示 1/3、2/3、3/3、4/6、5/6、6/6。下一档开始时按该档所需的新增人数重置分段，所以第四人是第二组三段中的第一段；已有的一条横杠保留。只有一个人数档的盟约达到后维持该档分母。

调和的激活人数加成按当前目标条件处理，详情可见实体人数；独行失效时取消亮段与横杠。装备和精锐状态变化会实时更新速览。下方重复的盟约统计区域已移除。26 个盟约图标缓存于 `assets/pacts/`。
